# 0005 — Web com Next.js 16 + stack de estado/formulários

- Status: aceito
- Data: 2026-07-18

## Contexto

O produto web precisa de páginas públicas indexáveis (marketing/SEO) e do app autenticado, compartilhando lógica com o mobile.

## Decisão

- **Next.js 16 (App Router, Turbopack)** + **Tailwind CSS 4** para o app web.
- **Compartilhar lógica, não UI**: web e mobile têm árvores de componentes próprias; domínio (`core`), contratos, api-client e hooks são compartilhados.
- Estado/dados (padrão para web **e** mobile): **TanStack Query 5** (server state), **Zustand 5** (client state), **React Hook Form 7 + Zod 4** (formulários, mesmo schema do contrato).

## Alternativas consideradas

- **Expo web (react-native-web) para tudo** — maximiza compartilhamento, mas penaliza SEO/SSR, semântica DOM e "web-feel"; consenso 2026 é usá-lo só para expor o app no browser, não para site de produto.
- **TanStack Start** — v1 com adoção explosiva e ótimo type safety; ainda jovem em ecossistema/hosting. Next.js é o default maduro; revisitar se a complexidade RSC incomodar.
- **TanStack Form** — alternativa moderna com Standard Schema; RHF escolhido pela maturidade/fricção menor no MVP (troca barata depois, schema é o mesmo).
- **Redux/Jotai** — sem vantagem sobre Query+Zustand para nosso perfil.

## Consequências

- (+) SEO/performance web de primeira; UI idiomática por plataforma; toda a lógica de negócio escrita uma vez.
- (−) Duas árvores de UI para manter (custo aceito conscientemente; tokens de design compartilhados via Tailwind/NativeWind).
- (−) Next.js 16 tem relatos de memory leak em containers (jan/2026) — alvo primário é Vercel; pinar patches.
