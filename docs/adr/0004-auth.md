# 0004 — Autenticação com Better Auth (self-hosted)

- Status: aceito
- Data: 2026-07-18

## Contexto

Auth precisa funcionar em web (Next.js) e mobile (Expo), suportar e-mail+senha no MVP e crescer para OAuth social, 2FA, passkeys e billing premium — sem custo proibitivo em escala.

## Decisão

**Better Auth 1.x** self-hosted dentro da API (rotas `/api/auth/*`), com adapter **Drizzle** (tabelas no nosso Postgres), plugin **Expo** para mobile (deep-link OAuth + SecureStore) e sessões em cookie HttpOnly no web. Configuração compartilhada em `packages/auth`.

## Alternativas consideradas

- **Clerk** — melhor out-of-box UX e ótimo SDK Expo, mas SaaS lock-in e custo em escala (~US$ 2k/mês a 100k MAU vs custo do próprio banco); dados de usuário fora do nosso Postgres.
- **Auth.js (NextAuth)** — em modo manutenção desde que o time se juntou ao Better Auth (2025); não é opção para projeto novo.
- **Auth artesanal** — reinventar sessões/reset/verificação é risco de segurança sem ganho.

## Consequências

- (+) Dados de auth no nosso banco; custo ≈ zero; plugins cobrem o roadmap (2FA, passkeys, organização, **Stripe** para premium).
- (−) Operação de segurança é nossa: rate limit nas rotas de auth desde o MVP, entrega de e-mail, monitoramento ([security.md](../security.md)).
- (−) Lib jovem (1.x): versão pinada, changelog acompanhado.
